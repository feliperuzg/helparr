Self-hosted web companion for Sonarr, Radarr and Prowlarr — one queue across every instance that flags stalled downloads, plus manual search and grab, missing-episode hunting and rename previews.

It talks to your already-configured stack over its own APIs and gives you the operations those tools bury or omit. A companion, not a replacement: Sonarr and Radarr stay the source of truth.

Run it 
docker run -d --name helparr \
  -p 3000:3000 \
  -v helparr-data:/data \
  -e HELPARR_ENCRYPTION_KEY="$(openssl rand -base64 32)" \
  -e HELPARR_INITIAL_PASSWORD='replace-me' \
  ghcr.io/feliperuzg/helparr:latest

The package is public, so the pull needs no token and no docker login. Then open http://your-host:3000 and sign in with the password you set.

What it is

The tail your *arr stack leaves you in

Sonarr and Radarr automate acquisition well in the common case. The tail is where it stops: a release the built-in indexer search won't surface, a season with three episodes that never matched, a directory imported before you changed the naming scheme.

Today those are resolved by hopping between four web UIs, a torrent client, and occasionally the filesystem. helparr collapses that into one screen.

Four things it does

  • Arbitrary indexer search — query Prowlarr directly, across indexers, and grab a release to a target you pick.
  • Library gaps — every monitored series and film with no file, in one list, with manual attach.
  • Bulk rename — the full diff first, confirmed before a single write is issued.
  • Unified queue & health — what every instance is doing, and which ones are degraded.

Screens

Four screens, nothing hidden

Overview

Every instance's health and one queue across all of them. Sonarr calls the stalled row healthy, because it handed the release to the client and has nothing further to say about it; helparr disagrees from the client's own evidence. Surfacing that disagreement is what this screen is for.

Indexer Search

Free text across every indexer Prowlarr manages, with the filters the *arr UIs omit, and a grab to a target you pick.

Gaps

Everything monitored with no file, from both Sonarr and Radarr, in one list. Attach a specific release to a specific episode, or a season pack to a season.

Rename

The complete diff first. Nothing has moved at the moment this is on screen, and the confirmation asks you to type the file count before anything does.

These are generated, not captured by hand: npm run build:screenshots drives the real production build in a browser against stub *arr servers. Every title, path and release name above is invented, and the images go stale loudly rather than silently.

Install

One container, two required values

The image is multi-architecture and served from one tag, so the same line works on an Intel NAS and on Apple silicon — you never pick an architecture.

What you need

  • A Docker host — no Node, no compiler, no Python: the image already carries the compiled modules for its architecture.
  • A running Sonarr, Radarr and/or Prowlarr to point it at, plus its API key.
  • An encryption key and an initial operator password. Compose refuses to start without them rather than falling back to a default.
  • A persistent volume for /data. The database and its WAL sidecars must stay on one mount.

Running on bare metal instead needs Node.js 20.9+ and a build toolchain, because the native modules compile on install. The README covers the systemd unit and the reverse-proxy setup.

Limits

What it deliberately does not do

It issues real writes

A grab is a grab, an attach asks Sonarr to import, and a rename moves files on disk through the *arr APIs. None of it is reversible by helparr, and the *arr APIs offer no rollback either. Every destructive path sits behind a preview you have to confirm, and that preview is the entire safety net — so read the diff.

  • No multi-tenancy, no public exposure. One operator, one trusted network. There is no user model, no roles, no sharing.
  • It does not replace Sonarr or Radarr. No scheduling, no quality profiles, no import logic, no library database of its own.
  • It never touches the filesystem. Every write goes through the *arr APIs.
  • It ships no indexers and no content. Prowlarr keeps that job.
  • It terminates no TLS. Put it behind the reverse proxy you already run.
  • There is no hosted instance and no demo. The only way to see it running is to run it.

Built for self-hosters and homelab operators who already run a fully configured stack and are comfortable with API keys, indexer semantics and release-group naming. If that is not you, this is the wrong tool.
